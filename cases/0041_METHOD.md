# 0041 生成方法与检查记录

唯一场景输入是本例 first_frame.png 和 prompt.txt。先打开原图、另存四倍放大检查图，再写 OBSERVATION.md；没有读取其他 case 或旧生成器，没有联网、AI API、学习权重、物理引擎或三维渲染。

## 像素生成方法

generate.py 在四倍分辨率的二维数组中分别重绘左右橘块和刀，再抗锯齿到 256×144 RGB。左右橘块轮廓来自独立手写二维曲线，逐帧计算小幅外倾和底部支撑点位移。外皮按单独的外侧圆弧距离生成，中心新切边不用外皮色；左右白内皮在上部和外侧较厚，下部较薄。果肉先用多个手写不规则瓣膜区域给出不同的浅红橙、深橙和暗褐色，再重绘数百个有实际宽度的椭长汁囊、细小湿润亮边和小面积柔亮斑。白筋由左上卷曲瓣膜、右上环状残膜、粗细变化的中央纤维和几十条随机短分支组成；中央另用有宽度变化的灰粉白纤维褶皱与较暗凹部表达厚度。颜色采用二维空间函数、固定噪声和局部色斑，全部直接计算新 RGB，没有裁取源物体像素搬运。切口侧缘、轻微压缩、纹理、钢色刀刃和贴地阴影均逐帧重新求值。

没有把原橘子裁成贴图移动、镜像或缩放。背景修补仅取离橘子至少约 70 像素横向距离的静止玻璃切板像素，并在修补区边缘羽化；原刀所在的细窄背景按两侧空切板插值。最初 01–04 帧用同一坐标处的原始 RGB 与重绘 RGB 按 20%、43%、67%、86% 渐进混合，让物体尚未明显分离的最初阶段保持摄影材质连续；05 后完全重绘。此混合不移动源图像素。00 直接逐像素保留原图。

假设是刀已进入中心切线，继续完成这一次切割；不是另加一次横切。两瓣是原半个橘子的两个四分之一块。每块最外向位移 2.35 像素、外倾约 2.8°，底部支撑点始终在 y≈85。刀保持首图侧刃方向，完成切割后从上方抬出。画外操作者、背部厚度及真实刀柄未知，没有补画。

## 实际视觉检查与修正

1. 最初实际查看 first_frame.png 与 first_frame_enlarged.png，检查外轮廓、切板划痕、刀与中心白筋的前后关系，以及底部支撑。
2. 第一版实际打开 inspection.png 的 00、02、05、08、11、14、17、19 八时点，又打开 transition_check.png 的 00/01/02 放大对比及 05/08/11/14/17/19 接触/遮挡图。发现背景修补错误地从太近处取到橘子，产生左右橙色残影；还发现重绘白筋过直、果肉过平滑。
3. 修正静止背景取样距离，移除残影；给白筋加入弯曲、增加多尺度果肉色差和细汁囊；加入中心灰白纤维。实际重开两张检查图确认残影消失。
4. 再修正背景修补的矩形边界，增加 6 像素羽化，把两个贴地阴影中心对齐 y≈85 的实际支撑点。最终再次实际打开两张检查图，复查八时点和 00/01/02 放大图：外皮厚度、轮廓尺度没有骤变，没有第三块、重复刀影或浮空块；刀经过 14 帧时下方切口显露，17 帧已脱离果肉，19 帧全部退出。静止木桌和切板没有整体移动。

## 仍然可见的局限

- 返修已减少规则放射色块并补回厚薄不同的白内皮、卷曲白筋和较宽中央纤维，但程序重绘的组织仍比真实照片均匀，尤其白筋边缘和湿润高光的复杂度有限；细看 00 与 05 仍能辨认照片和程序材质的差异。
- 只在可见二维切面上表达轻微倾斜、外侧皮层和新切边，没有显示不可见的背部果皮。因此皮肉层厚度有改善，整体仍缺少真实转动时的背面体积信息。
- 橘子遮住的玻璃划痕无法恢复；修补区细纹是真实附近静止背景的近似，局部比原图稍平滑。
- 没有可见手和完整刀身，只沿首图窄刀刃解释动作，真实受力和汁液细节未恢复。
