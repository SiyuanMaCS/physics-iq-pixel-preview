METHOD.md

METHOD

Task

20 RGB frames, 256×144, 4 fps, 5 s, locked-off camera. Frame 00 is byte-identical to first_frame.png (asserted in generate.py and re-checked after saving). Only content change in the scene: the grey tennis ball rolls out of the black pipe at the left and travels rightward across the light-wood coffee table.

All pixels are produced with local Python math/imaging only (NumPy + Pillow + SciPy ndimage): no external models, engines, or assets.

Measurements (from first_frame.png)

  • Ball disc (B−R coolness mask): centre (109.3, 75.5), soft radius ~7.3 px horizontal / ~7.5 px vertical (defocus/fuzz halo to ~10 px), contact line y ≈ 82.5.
  • Right tabletop perspective edge (rightmost table pixel per row) fits x_edge(y) = 209 + 0.63·(y − 66). Constant-depth rolling ⇒ image y constant.
  • Faint cast shadow to the right of the ball: x ≈ 117–142, y ≈ 78–84, only ~3–10 % darkening; light from upper-left.

Motion model

  • Constant velocity v = 5.30 px/frame: cx(t) = 109.3 + 5.30·t, cy = 75.5. At frame 19 cx = 210.0, i.e. the ball finishes ~2 px inside the measured right table edge; it stays on the table for the whole clip.
  • No-slip rolling about an axis pointing roughly at the camera, so the visible texture rotates in the image plane: clockwise ω = v/r ≈ 0.73 rad/frame (~42°/frame, ≈ 2.2 turns over 5 s — equal to travelled-distance/radius).
  • Every non-ball pixel is static across all 20 frames.

Pipeline (generate.py)

  1. Clean table plate. A generous corruption mask (disc ∪ contact ellipse ∪ shadow-tail ellipse) is dilated 3 px for the fill domain; each masked row is rebuilt from the mean of clean sampling windows 4–14 px on either side of the corruption (capped to the table polygon), linearly interpolated to keep the gentle horizontal brightness gradient. Wood bands run horizontally, so row-wise reconstruction preserves them exactly. A Gaussian-blurred mask (σ 2.0) feather-blends the fill into the original.
  2. Ball sprite (RGBA) extracted from frame 00. Soft coverage alpha from the max-channel colour distance to the plate, with a core override and a geometric cap to exclude the cast tail; plate colour mixed into soft edges is unmixed (ball = plate + (orig − plate)/α).
  3. Shading vs. detail decomposition. Premultiplied Gaussian blur (σ 2.4) gives the fixed sphere shading (bright top, dark lower-right); the ratio layer detail = ball/shading carries the white seam. Only the detail layer rotates.
  4. Per-frame render. The detail layer is bilinearly rotated about the disc centre by −ω·t (scipy.ndimage.map_coordinates), multiplied back onto the fixed shading, and 7 sub-steps over a 20 % shutter are averaged for slight spin/translation blur matching frame 00's softness. The sprite is pasted at (cx(t), 75.5) with sub-pixel offsets; a feathered table-edge mask clips the last 3–4 frames.
  5. Cast shadow. A fixed Gaussian blob (centre offset (+9.5, +5.5), σx 9.0 / σy 2.3) with a Gaussian disc exclusion is translated with the ball and clipped to the measured table polygon. Its amplitude is fit by least squares to the frame-00 shadow residual (A ≈ 0.12, ~8 % peak darkening after exclusion) and is applied before compositing the ball.
  6. Outputs are written through artifact_io.save: pixels.npz (H×W×20 uint32 0xRRGGBB), 20 PNGs, the 8-frame inspection.png, and the standalone index.html player.

Honest limitations

  • The sphere is rendered from one measured view: shading is the blurred frame-00 sprite (not a true BRDF), and the seam pattern is a 2-D rotation of the extracted detail layer rather than a full 3-D tennis-ball texture; this is exact for rotation about the viewing direction, which the setup approximates.
  • Velocity is constant (no friction model); the event ends with the ball at the right table edge rather than falling off, matching the prompt's "towards the right" without inventing an unshown fall.
