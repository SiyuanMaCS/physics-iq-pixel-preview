METHOD.md

METHOD — case_0021

Task

Continue first_frame.png (256×144) into 20 frames at 4 fps: the yellow-green tennis ball rolls out of the left black pipe, across the wooden table, onto the cardboard ramp, climbs toward the propped-up end, stops and rolls partway back. Only local Python pixel operations are used (NumPy / Pillow / SciPy ndimage); no external models, engines or image sources.

Scene measurements

All geometry was measured directly from first_frame.png (see OBSERVATION.md): pipe mouth ≈ (7,39); ball centre (62.5,44.7), radii rx 7.4 / ry 6.6, contact (62.5,50.9); ramp quad corners C(123,73), D(131,41), A(230,9), B(240,45); blue support block x196–225, y50–85; ball cast-shadow centroid ≈ (49,42). Wood grain is horizontal with a smooth per-row gradient; the key light comes from the lower-right.

Static background reconstruction

Every generated frame starts from one shared static canvas bg built once:

  1. F0 is copied; only the frame-0 ball ellipse and its cast-shadow rectangle (plus a 1 px dilation) are treated as missing.
  2. Each missing pixel is filled on its row by linear interpolation between the nearest clean table pixels on the left and right, plus a small horizontal grain residual copied from a clean strip of the same row. The faint static shadow cast by the raised ramp (x ≈ 92–110) survives because it lies outside the filled region. This leaves pipe, block, ramp, background and all static shadows as the exact original pixels (verified byte-identical in those regions).

Ball and shadow sprites (sampled from frame 0)

  • Alpha matte α = clip((G−B−8)/40,0,1) · clip(1.15−q,0,1) with q = ((x−62.5)/8.6)² + ((y−44.7)/7.9)², restricted to the connected component at the ball.
  • Un-pre-multiplied ball colour C_ball = (F0 − bg·(1−α))/max(α,0.06), so re-compositing bg·(1−α)+C_ball·α at the original pose reproduces frame 0 to mean error < 1 level on α>0.5 pixels.
  • Shadow stamp: per-pixel neutral darkening ratio bg/F0 inside the shadow footprint (green ball rim excluded by colour and α masks), converted to a weight map and Gaussian-smoothed (σ≈0.9). The stamp anchor is the shadow's brightness-weighted centroid; it is translated with the ball contact point (offset ≈ (−13.5,−8.9)) and applied multiplicatively, which darkens either wood or cardboard consistently.

Motion (analytic image-space physics)

  • Table: contact moves from (62.5,50.9) along d_t=(0.997,0.076) at constant 60 px/s; hinge at arclength 65 px reached at t=1.083 s.
  • Climb: along d_r=(0.964,−0.265), u = 60τ − 13τ² (26 px/s² deceleration); apex u=69.2 at τ=2.308 s (t≈3.39 s, near frame 14) at centre ≈ (192,32).
  • Roll-back: u = 69.2 − 10(τ−2.308)².
  • Ball centre = contact + surface normal easing from (0,−6.2) to (−1.6,−5.9); sprite scale eases 1.00→0.93 with height (perspective).
  • A ~4.5 px directional smear of the sprite (cubic smoothstep fade) is added in proportion to speed to emulate the 4 fps exposure; zero smear at apex.
  • Bilinear sampling of the 20×17 sprite supports sub-pixel positions.

Outputs and verification

generate.py renders all 20 frames, frame 00 being an untouched copy of first_frame.png, then calls artifact_io.save to write pixels.npz (uint32 0xRRGGBB, shape 144×256×20), frames/00..19.png, inspection.png and the standalone index.html. Numeric checks confirmed:

  • frames/00.png is exactly equal to first_frame.png;
  • every PNG equals the corresponding tensor slice after 0xRRGGBB packing;
  • pipe, blue block and other static regions are byte-identical across frames;
  • the ball stays inside the ramp quadrilateral, peaks near frame 14 (only 75 pixels change 13→14) and accelerates again while rolling back;
  • changed pixels per transition (382 → 75 at apex → 202) match the accelerate/stop/reverse dynamics.

make_transition_check.py writes transition_check.png (per-frame gray base with amplified red changed pixels vs the previous frame; panel 00 vs first_frame.png is empty). Inspection was performed only through local code and numeric/ASCII checks — no image viewing tool was used.
