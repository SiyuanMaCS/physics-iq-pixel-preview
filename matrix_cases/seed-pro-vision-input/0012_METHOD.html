ball-hits-nothing · 生成方法

Task

Continue a locked-off, constant-framerate (4 fps, 20 frames, 256×144) shot of a light wood coffee table. Prompt action: the orange tennis ball rolls straight out of the black pipe over the entire table toward the right side. Everything else (pipe, smaller red ball, brown tennis ball, their shadows, couch, floor) is static.

All measurements below were obtained numerically from first_frame.png (threshold masks, pixel dumps, row/column medians); see OBSERVATION.md. No image viewing tool was used to judge generated frames — verification is numeric only.

Physical model read from frame 0

  • Orange ball: bbox x31–43, y39–50, centroid (36.7, 44.8), diameter ≈ 12 px; only a ~1 px horizontal motion smear (short exposure relative to the 0.25 s frame interval).
  • The ball casts a soft elliptical shadow offset ≈ (+13, +2) px from its centre (light from the left), covering roughly x42–62, y43–52.
  • Motion is purely horizontal: the frame-0 smear is along x and the table edges are horizontal in the image, so the path is a constant-y straight roll at y ≈ 45. Apparent size is constant (path parallel to the table edges).
  • Open-table wood varies only ±2–4 within a row outside the ball hole; the only strong x-gradient at this height is the pipe's cast shadow near x24–30. The table surface ends at x ≈ 218 at ball height (dark floor past x ≈ 221).

A constant-velocity roll with fixed exposure therefore presents the same ball+shadow image at every frame, translated horizontally. The generator exploits exactly that: it reuses the frame-0 ball/shadow appearance as the sprite, so frames 1–19 are automatically consistent with frame 0 (same blur, same shadow, same colours).

Pipeline (generate.py, local numpy + PIL only)

  1. Frame 0 is copied byte-for-byte from first_frame.png (verified: the re-encoded frames/00.png is file-identical, 44209 bytes).
  2. Clean table plate. The single frame-0 region covered by the ball and its shadow (hole x30–62, y39–52) is inpainted:
    • per row, ambient colour is linearly interpolated between the nearest real wood columns on each side (x29 and x63), giving C0-continuous seams and naturally preserving the pipe-shadow ramp on the left;
    • small (±2) per-channel grain deviations, taken from same-row clean donor columns x67–94, are tiled across the hole with a deterministic per-row phase (seed 12) and feathered off at the two outer columns. Measured seams: horizontal ≤1 mean RGB step (natural inter-pixel step ≈0.81, p95 2); vertical ≤3.9 mean / 17 max, within the natural row-to-row banding (mean 5.4, max 29).
  3. Sprite extraction. Residual frame0 − plate over support x29–63, y38–53; the outer border (real, untouched wood) is forced to zero, so the sprite fades directly into live table pixels on every side. Residual range ≈ +115 (orange core) / −53 (shadow core).
  4. Rendering frames 1–19: frame_k = clip(plate + sprite shifted +9·k px horizontally, same y). Integer pixel shifts, no resampling, no rotation (at 12 px the fuzzy orange ball carries no orientable texture, and frame 0 shows none; translation plus the cast shadow and motion smear convey the roll). 9 px/frame takes the centroid from 36.7 to 207.7 over 5 s (≈0.17 m/s for a ~1.2 m table); the ball ends ~6 px before the table edge, fully visible on the tabletop at the right side.
  5. Outputs are written through artifact_io.save: 20 PNGs, the packed 0xRRGGBB uint32 tensor in pixels.npz (shape 144×256×20), the inspection.png contact sheet, and the standalone delta-encoded index.html player. transition_check.png is a 1280×302 diagnostic strip: key frames (00/04/09/14/19) on top and their amplified inter-frame absolute differences below.

Numeric verification (all PASS; script in .tmp/verify.py)

  • frames/00.png pixel- and byte-identical to first_frame.png.
  • pixels.npz tensor equals all 20 PNGs packed as 0xRRGGBB; unpack round-trip exact; the player's base64+deltas reconstruct all frames exactly.
  • Union of all changed pixels vs frame 0: x30–233, y39–52 only; 0 pixels change outside the swept band. Pipe, red ball (x93–100, y30–37), brown ball, couch, floor and front table are pixel-identical in every frame.
  • Recovering the plate independently as the temporal median of all 20 frames, frame_k − plate is exactly the same residual translated +9 px with identical row support [39,52] for every transition k=0..16 (max error 1 level from median rounding) — proving constant-velocity, zero-vertical-motion, constant-pose motion.
  • Ball orange mask left edge advances exactly 31 → 202 in +9 px steps; final right edge x211 ≤ table edge (~218); per-transition change count 582–583 pixels.

Known approximations

  • Compositing is additive (plate + residual). Around frames 6–8 the ball crosses the faint tail of the static red ball's cast shadow (a few partially-covered top-edge pixels near y40, x99–103); those pixels end up up to ~12 levels darker than on evenly lit wood, which reads naturally as the ball passing over a slightly darker table patch.
  • In the last two frames the soft shadow tip reaches the dark table-edge / floor (x≥220); 58 channel values clamp to 0 on already near-black floor pixels (no visible effect). The ball disk itself never leaves the tabletop.
