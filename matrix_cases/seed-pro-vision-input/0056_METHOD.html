Method outline

  1. Build a clean background plate from frame 0 by removing the stick dowel and the four right dominoes, filling holes with matched platform-dark per-row samples or synthesized horizontal-grain wood (base row color + stretched multi-octave noise, 2-px feathered blend).
  2. Cut RGBA sprites of each right domino (hand quads + 1-px dilation) and the stick (tan-color mask below the hub) from frame 0.
  3. Per frame: paste plate → soft moving contact shadows → rotate each domino sprite about its base center with angle from a gravity-style integration (α∝sin θ), triggered by geometric tip-to-next contact → paste rotated stick about the hub. Frame 0 is the untouched original.
  4. Save via artifact_io.save; verify f00 byte equality, PNG/tensor round-trip, and per-frame changed-pixel continuity numerically (no image-viewing tools used for later frames).

METHOD — case_0056

What happens

The wooden dowel on the black platform rotates clockwise, strikes the rightmost black domino (B4), and the black/white chain B4→W4→B3→W3 topples right-to-left until W3 is stopped by the yellow rubber duck. The four dominoes left of the duck, the duck, and the platform body never move.

Method (local Python pixel operations only)

All rendering is in generate.py using NumPy + Pillow (+ scipy only for a Gaussian blur on a noise field). No external models, engines, or reference images are used.

  1. Measurement. Coordinates were extracted from first_frame.png purely numerically (color masks, connected components, per-pixel RGB dumps): domino quads, base line (y = 90), block height (27 px), pivot base centres, hub centre (212, 49), dowel segment and colour, table colour, and the duck flank (x ≈ 153). See OBSERVATION.md.
  2. Background plate. The four right dominoes (hand-traced quads dilated 1 px) and the dowel are removed. Domino holes are filled with synthesised wood: per-row mean colour sampled from clean table columns, plus a horizontally stretched Gaussian noise field whose standard deviation matches a measured clean-table patch (the real grain is strongly horizontal). Dowel holes on the platform are filled from per-row dark-platform samples. The fill is strict to the mask, so at rest the original sprites cover it exactly and standing regions stay byte-identical to frame 0 (verified).
  3. Sprites. Each domino and the dowel are cut from frame 0 as RGBA sprites (quad/distance masks). Dowel pixels overlapping B4's corner are repainted dark in the B4 sprite so they move with the dowel.
  4. Rigid animation. Each frame, sprites are rotated with bilinear resampling (alpha gated above 110/255 to kill fringes) about their fixed base pivot (dowel about the hub), located by a rotated marker point so pivots stay fixed to sub-pixel accuracy. Domino angles follow smoothstep ease-in-out falls keyed at frames 2/4/6/8 (B4/W4/B3/W3) over 6 frames, then each angle is clamped by geometric tip-to-tip contact: a falling block cannot pass the tip of the block already leaning toward the duck, and W3 cannot pass the duck flank (x = 154). A small damped recoil on W3 after arrest keeps the last frames alive. Final stack: W3 ≈ 25° against the duck, B3 ≈ 63°, W4/B4 ≈ 87°. Block tips legitimately occlude the duck's right edge (x150–153, y64–82) where they contact it.
  5. Dowel motion. Eased 73° clockwise rotation from its measured initial screen angle (~110°) to ~183° (pointing left) across frames 0–9, then held; the tip contacts B4's top around frame 2, one frame before B4 visibly tips.
  6. Shadows. A soft blurred dark contact shadow is drawn under each block once it starts tipping, hard-clipped to x ≥ 154 so it never darkens the duck; each sprite also carries its original 1-px baked contact shadow.
  7. Output. artifact_io.save writes pixels.npz (H×W×20 uint32 0xRRGGBB tensor), frames/00.png–19.png, inspection.png and index.html; transition_check.png is an extra crop/heat-map montage of frames 0,2,4,6,8,11,14,19.

Verification (numeric; later frames were never opened with an image tool)

  • frames/00.png is pixel-identical to first_frame.png.
  • Every PNG exactly matches the packed 0xRRGGBB tensor in pixels.npz.
  • The base64 deltas in index.html reconstruct all 20 frames exactly.
  • At frame 1 the only changed pixels lie on the dowel (63 px); standing domino interiors and everything left of x 185 are unchanged.
  • Left side of the scene (x < 154, i.e. duck and all left dominoes) stays unchanged in every frame.
  • Filled wood patches match clean-table per-row colour/statistics.
  • Pivot base rows stay fixed (lowest dark pixel per block stays at y ≈ 90).
  • Frame-to-frame changed-pixel counts stay nonzero through the recoil and show continuous, monotonic cascade propagation (tip x-positions tracked per frame).
