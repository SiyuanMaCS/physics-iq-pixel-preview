Rendering method (preview; details in METHOD.md)

METHOD.md

METHOD — case_0065

What was generated

20 RGB frames, 256×144, 4 fps (5 s), continuing the mid-pour in first_frame.png: the dispenser keeps pouring bright-red liquid into the tumbler, the glass fill rises (surface band y≈92 → y≈78, +14 px), and the dispenser jar meniscus drops (≈7 px, set by the 36:72 inner-width ratio). Camera, basket, table, walls, glass walls and spigot remain static.

Method (local numpy/PIL pixel operations only)

Everything was computed from first_frame.png; no external models, engines, images or network were used.

  1. Scene measurement (numeric, no image-view tools). Threshold masks and row/column scans located the jar liquid windows (x103–130 and x146–174, avoiding the spigot), the per-column jar meniscus rows, the stream footprint (x131–136, y64–95), and the tumbler interior (x115–151, straight-walled to y≈128). Region colors were sampled directly. Measurements and the 20-frame plan are in OBSERVATION.md.
  2. Rising fill. For each frame t, rows y in the straight glass interior are overwritten with frame-0 row y + rise(t) (linear interpolation between the two bracketing rows), so the existing turbulence/foam band and deep-red body translate upward intact. Only interior columns x115–151 and rows up to the new surface are touched; the curved base is never edited. Front-glass specular flecks (luminance > 175, excluding the stream column and fill body) are restored from frame 0 because they are reflections on the near glass surface and stay fixed.
  3. Dropping jar meniscus. Each jar window column has a per-column "empty ribbed glass" reference = median of that column's own rows above its original meniscus (keeps the vertical rib shading). Newly exposed rows are painted from that reference with a faint vertical shading and ±4 deterministic grain; a fractional first row is alpha-blended for sub-pixel motion. The original wavy meniscus profile is translated downward, redrawn as a 1 px dark-red line plus a faint highlight, with a slow ±1 px sine ripple.
  4. Flow animation. The stream footprint itself is not reshaped (so no background inpainting is needed): red pixels within x131–136 get a frame-varying sinusoidal brightness flutter and a varicose "necking" pulse; a Gaussian specular highlight travels downward (phase y − 4t), and the orange left edge pulses. The modulated column is clipped to the rows above the rising surface, so the visible jet shortens as the glass fills.
  5. Foam, droplets, bubbles. Deterministic hash functions of (t, i) place ~7 orange/pink foam flecks on the entry band, 0–2 one-pixel splash droplets above the impact, and ~6 small bubbles rising near the stream column; a 4.5% traveling sine shimmer modulates the turbulence band. All randomness uses fixed seeds/hashes, so output is reproducible.
  6. Serialization. artifact_io.save writes pixels.npz (uint32 0xRRGGBB, shape 144×256×20), the 20 PNGs, inspection.png (frames 1/3/6/9/12/15/18/20) and the delta-encoded index.html player. transition_check.png shows frames 1, 10, 20 and an amplified |f20−f1| change panel.

Verification performed (numeric only)

  • frames/00.png is byte-exact vs first_frame.png (array equality).
  • All 20 PNGs pack to exactly the pixels.npz tensor as uint32 0xRRGGBB.
  • The embedded player's first frame and its 19 delta streams reconstruct all 20 frames to exact PNG equality.
  • Changed-pixel bbox stays inside the jar (y29–47, x103–174), stream/glass (x115–152, y64–122); sampled wall/table/basket pixels never change.
  • Glass fill trends upward (surface detector 96 → 79 px, with ±2 px turbulence flicker expected from the animated foam band); jar red pixel count decreases (197 → 93 in the y36–46 window); stream-alive test positive every frame; frame-to-frame mean abs change ≈0.18–0.29 with no temporal spikes.
  • No image Read/View tools were used on generated frames; visual plausibility was assessed through ASCII classification maps and region-color statistics only.
