METHOD.md

Method and verification

This sequence was generated entirely with local Python pixel operations using first_frame.png and prompt.txt. The input was inspected through numeric RGB values, component coordinates, and statistics. No image Read/View tools, network, external references, AI models, external rendering engines, or subagents were used. The saved image sheets have not been visually reviewed.

Pixel construction

generate.py reads the original photograph with Pillow and NumPy. It retains the fixed camera plate, pipe, table edges, and background. Only the source ball and shadow footprints are repaired. The repairs interpolate the same-row neighboring table illumination and add fine grain from unobstructed same-row pixels elsewhere in this same input. Feathering confines each repair to its measured footprint.

Subtracting this plate from the photograph produces signed RGB residual sprites containing the original spheres, their soft shadows, and the orange ball's weak reflected tint. Complementary horizontal weights separate the touching brown/orange pair. Bilinear coordinate translation moves these sprites to subpixel positions. Sphere interiors are then composited over the shadow layers, so another ball's translated ground shadow cannot darken the sphere surface. The surface RGB starts from the photographed ball itself.

Rolling texture uses analytic sphere coordinates. Source surface RGB is divided by a simple fixed diffuse shading estimate; inverse rolling rotations sample that surface texture. The unknown rear hemisphere uses a mirrored extension of the measured front surface. The resulting texture difference is reapplied to the photographed sphere with the lighting direction held fixed. Soft radial mattes and bounded texture changes retain the input silhouettes, shading, and color. This is image-based local pixel compositing with mathematical texture warps, not a reconstructed 3D scene.
