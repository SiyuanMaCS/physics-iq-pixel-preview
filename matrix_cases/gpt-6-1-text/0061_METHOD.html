duck-static · 生成方法

The scene is a locked camera recording of a yellow rubber duck sitting stationary on a wooden table. The prompt describes no time-varying action. Accordingly, all 20 frames repeat the exact source RGB pixels. This is a local pixel-copy method using Python, NumPy, and Pillow. It uses no animation model, physics engine, external references, network requests, or subagents.

OBSERVATION.md was written before generate.py, recording numerical source measurements and the complete 20-frame plan. The input image was inspected only by local decoding, RGB statistics, and connected-component measurements. No image Read/View tools were used, and no visual review is claimed.

Generation

  1. Decode first_frame.png as RGB uint8, requiring dimensions 256 × 144.
  2. Repeat that array 20 times. Preserve camera position, subject geometry, existing lighting, background shading, and wood texture exactly.
  3. Use the supplied output-only artifact_io.save helper to write the PNGs, tensor, contact sheet, and self-contained HTML player. Pack each pixel as (R << 16) | (G << 8) | B. Store the tensor under key pixels, with dtype uint32 and shape (144, 256, 20) (height, width, time).
  4. Copy the original PNG file to frames/00.png, retaining both pixel identity and byte identity.
  5. Draw transition_check.png from all 19 adjacent absolute RGB differences. Each difference image is black because every RGB channel remains constant; the labels report the changed-pixel count.
  6. Verify the saved outputs and write verification.json.

The 4 fps sampling times are 0.00, 0.25, …, 4.75 seconds. Each sample displays for 0.25 seconds, giving a 5-second sequence. The HTML player uses a 250 ms interval and contains the first packed frame plus 19 empty delta packets.

Results

Local execution of generate.py passed all checks:

  • Exactly 20 RGB PNG frames at 256 × 144.
  • Frame 00 equals the source PNG byte for byte and pixel for pixel.
  • All frames equal the source RGB array.
  • All PNGs equal their corresponding uint32 0xRRGGBB tensor slices.
  • Tensor shape (144, 256, 20), dtype uint32, key pixels.
  • All 19 adjacent transitions have zero changed pixels and a maximum channel difference of zero.
  • Every frame reconstructed from the actual embedded HTML packets equals its tensor slice; the player specifies a 250 ms interval.
  • Inspection and transition sheet PNG encoding validates with Pillow.

These are code and numeric checks. Browser playback and image-tool visual inspection were not performed. The stationary prompt supplies no deformation or movement to simulate, so the sequence intentionally has no pixel changes.

Artifacts and reproduction

  • pixels.npz: packed RGB tensor.
  • frames/00.png–frames/19.png: full RGB sequence.
  • inspection.png: eight-frame contact sheet from the supplied helper.
  • transition_check.png: all adjacent RGB differences and their counts.
  • index.html: standalone 4 fps player, with embedded pixels.
