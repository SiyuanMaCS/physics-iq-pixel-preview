ball-rolls-on-glass · 生成方法

Approach

All 20 frames (256×144 RGB, 4 fps) are generated with pure NumPy / SciPy / OpenCV pixel operations — no external models, no network.

Pipeline

  1. Ball detection — Connected-component analysis on the R-channel (R < 20) isolates the tennis ball as the largest dark blob in the bottom-centre of first_frame.png.

  2. Background inpainting — cv2.inpaint (Telea algorithm) fills the original ball location using surrounding table/glass pixels.

  3. Ball sprite — A 66×66 soft-alpha RGBA patch extracted centred on the ball centroid with generous padding (14 px beyond the ball radius). Alpha = linear smoothstep from R = 5 (core) to R = 20 (edge). Below-frame ball pixels are synthesised from a radial colour profile sampled from visible ball pixels so the sprite contains a complete circular ball. Rotating this padded sprite does not bring transparent corners into the ball region.

  4. Shadow — A soft darkening patch derived from the background‑minus‑original difference at the ball location and displaced in lockstep with the ball.

  5. Frame loop (t = 1…19):

    • Ball centre moves rightward at constant velocity (≈3.42 px/frame, 65 px total) along a horizontal line.
    • Ball sprite rotated via scipy.ndimage.rotate (order‑1 bilinear, constant‑mode) by −Δx / r radians to model rigid rolling‑without‑slip.
    • Rotated sprite alpha‑composited onto the inpainted background.
    • Shadow patch applied multiplicatively under the ball.

  6. Verification — Frame 00 asserted bit‑identical to first_frame.png.

Physics

  • Rigid rolling without slip: angular displacement Δθ = −Δx / r (r ≈ 18.5 px).
  • Constant linear velocity — no acceleration or friction modelled (the 5‑second clip is short enough that constant motion is a reasonable first‑order approximation).

Tools

NumPy, SciPy (ndimage), OpenCV (inpaint), Pillow (Image) — Python 3 standard library only.
