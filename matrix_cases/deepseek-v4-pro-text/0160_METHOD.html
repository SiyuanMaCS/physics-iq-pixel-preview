METHOD.md

METHOD.md — Newton's Cradle Animation

Scene analysis

The input first_frame.png (256×144 RGB) shows a Newton's cradle on a table. Five metal balls hang from a metallic frame. The leftmost ball is held at amplitude by a blue-black grabber tool. The remaining four balls hang at rest, touching.

Key measurements obtained by pixel inspection:

  • Ball radius: 13 px (diameter 26 px)
  • Rest ball centres (y=72): (94,112,130,148,166)
  • Held ball centre at amplitude: (78, 73) — 16 px left of rest
  • Pendulum virtual string length: 120 px (chosen long to produce near-horizontal arcs matching the rendered image)
  • Grabber region: left side, x≈25-75, blue-black pixels (B > R+8, brightness < 100)

Animation strategy

Sprite-based compositing with background inpainting.

  1. Background plate: All ball footprints (5 rest + 1 amplitude) and grabber pixels are masked. The mask is inpainted with nearest-neighbour fill via scipy.ndimage.distance_transform_edt, producing a clean plate without balls or grabber.

  2. Ball sprites: Each ball is cropped from first_frame.png as a small square (32×32 px) centred on its position in the base image. A soft circular alpha mask (radius=13, feather=1.5 px) accompanies each crop. Ball 0 uses its amplitude position; balls 1–4 use their rest positions.

  3. Physics: Small-angle pendulum model with virtual string length L=120 px. The amplitude angle θ₀ = arcsin(16/120) ≈ 7.7°. Each half-cycle lasts 4 frames (1 s at 4 fps). Angular damping factor 0.82 per half-cycle. Collision is assumed instantaneous at the equilibrium point — the incoming ball stops and the far-end ball acquires the same speed (elastic, equal-mass).

  4. Rendering: For each frame the balls are alpha-composited onto the background plate at their computed positions (balls 1–3 stationary; balls 0 and 4 moving). The grabber is re-pasted from the original frame for frames 0–2, then omitted.

  5. Frame 0: Exact copy of first_frame.png — not rendered through the pipeline.

Output verification

  • Frame 00 byte-identical to first_frame.png ✓
  • All 20 frames 256×144 RGB uint8, values in [0,255] ✓
  • Changed pixel counts increase smoothly as balls move, consistent with the expected ~5% affected area ✓
