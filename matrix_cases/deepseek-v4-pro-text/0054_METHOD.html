20-Frame Event Plan (4 fps, 5 seconds)

Pendulum Physics Model

  • Simple pendulum: θ(t) = θ₀ × cos(ωt) × e^(-γt)
  • Natural frequency: ω = √(g_eff/L) — using pixel units with g_eff calibrated to give one half-period ≈ 7-8 frames
  • Damping: γ chosen so amplitude decays to ~60% after one full cycle
  • Collision handling: When 2 balls strike 3 stationary balls, the 2 outer balls on the far side acquire the velocity (momentum/energy conservation for equal-mass elastic collisions)

Implementation Strategy

  1. Extract ball sprites from frame 0 positions
  2. Create clean background by filling moving-object regions with nearby background estimation
  3. Simulate pendulum physics to compute ball positions for each frame

  5. Draw string lines from pivot points to ball centers

METHOD.md

METHOD.md

Approach

Frame 0 is an exact copy of first_frame.png. Frames 1–19 are generated by compositing extracted ball sprites onto a clean background, with positions driven by a damped pendulum simulation of a 5-ball Newton's cradle.

Scene analysis

  • Geometry: Measured from first_frame.png via luminance profiles, connected-component analysis, and dense ASCII visualisation.
    • Pivot bar at y = 48 px. String length L = 42 px. Ball radius r = 7 px.
    • Five ball centres at rest: x = 86, 100, 114, 128, 142; y = 90.
    • Two left balls pulled back by sin⁻¹(11⁄42) ≈ 0.265 rad.
  • Ball sprites: Extracted individually from each ball's position in frame 0 with circular alpha masks (1.5 px feather). This preserves per-ball lighting differences.
  • Clean background: Start from frame 0. Fill only the arc swept by the two left balls (from their pulled-back positions toward rest) and the arc swept by the two right balls (outward from rest). Rest-position pixels for balls 2, 3, 4 are explicitly protected from filling. The grabber tool region is untouched. Filling uses iterative distance-weighted median sampling with kernel sizes 3→5→7→11.

Physics

  • Model: Five equal-mass simple pendulums, coupled as a Newton's cradle.
    • Pendulum equation: θ̈ = −(g⁄L) sinθ − 2γθ̇, integrated with semi-implicit Euler.
    • g_eff = 5.0 px/frame², γ = 0.008 (light exponential damping).
    • Period T ≈ 18.2 frames; half-swing ≈ 9 frames.
  • Collisions: Detected when an active pair's θ crosses zero in the hitting direction. Momentum (angular velocity) transfers perfectly to the far-side pair. The centre ball (index 2) is stationary throughout.
  • State machine:
    • Frames 0–4: Left pair (balls 0,1) swings right from −0.265 rad to centre.
    • Frame 5: Collision → right pair (balls 3,4) acquires velocity, swings right.
    • Frames 6–13: Right pair swings out to peak (+0.245 rad), then back to centre.
    • Frame 14: Collision → left pair swings left (damped to −0.225 rad peak).
    • Frames 15–19: Left pair swings left and starts returning.

Rendering

  • Each frame starts from the clean background.
  • Dark-grey string lines are drawn from each ball's pivot to its current centre (only for displaced balls; strings for stationary balls use the original background).
  • Ball sprites are composited with their alpha masks, but ONLY for balls that are displaced from rest (|θ| > 0.001).
  • Balls at rest (including the centre ball always) use the original background pixels, ensuring zero compositing artefact when stationary.

Outputs

  • frames/00.png–19.png: 20 RGB frames, 256×144, uint8.
  • pixels.npz: uint32-packed tensor (144, 256, 20) — 0xRRGGBB encoding.
  • inspection.png: 8-frame contact sheet (1024×330).
  • transition_check.png: Clean background overlaid with red outlines of every ball position across all frames, plus green pivot dots.
  • index.html: Standalone delta-encoded player.
  • generate.py: This script (self-reproducing).
