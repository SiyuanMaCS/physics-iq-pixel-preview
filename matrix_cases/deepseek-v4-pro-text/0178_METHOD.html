METHOD.md

METHOD.md — Generation Approach

Overview

This is a pure Python pixel-manipulation approach. All 20 frames are generated programmatically from first_frame.png using only local NumPy/PIL/Scipy operations. No external AI models, physics engines, or network access are used.

Pipeline

1. Ball Sprite Extraction

The brown tennis ball is extracted from frame 00 as an RGBA sprite:

  • A 50×27 pixel region around the ball centre (141.5, 30.7) is analysed.
  • The local background brightness is estimated from the region's border pixels (median value).
  • Pixels darker than background − 12 are classified as ball pixels.
  • scipy.ndimage.label isolates the connected component containing the ball centre, producing a clean binary mask.
  • The mask defines the alpha channel; RGB values are preserved from the original frame. A 3-pixel margin is added for soft edges.

2. Background Inpainting

Only the brown ball region is inpainted (the grey ball is not yet visible in frame 00):

  • For each ball pixel (alpha > 0.3), the horizontally nearest background pixel (brightness > 60) within a 40-pixel scan radius replaces it.
  • This preserves the table's horizontal grain/texture while removing the ball.
  • The inpainted background is identical to the final frame 19 output (verified pixel-exact diff = 0.0).

3. Grey Ball Generation

Since no grey ball is visible in frame 00, one is synthesised from the brown ball:

  • The brown ball RGB is luminance-desaturated: 85% greyscale + 15% original colour. This preserves surface texture (the slight R/G/B variation seen in tennis ball fuzz) while shifting the colour to neutral grey.
  • Luminance is scaled to target average brightness ≈70 (vs brown ball's ≈40), matching the expected appearance of a grey tennis ball on the light table.
  • Small Gaussian noise (σ = 1.5) is added per pixel to avoid perfectly uniform R=G=B slabs that would look unnatural.

4. Frame Compositing

For each of the 19 generated frames (01–19):

  • Brown ball position: pos = (141.5, 30.7) + (−18, 0) × frame_index
  • Grey ball position: pos = (25, 75) + (15, 0) × (frame_index − 1.5) (only when ≥ 1.5)
  • Balls are composited onto the clean background using the alpha mask: output = bg × (1 − α) + sprite × α

5. Motion Blur

Horizontal motion blur models the camera's finite exposure time integrating over each frame interval:

  • For each ball, the alpha mask is convolved horizontally with a uniform kernel of width proportional to speed: blur_px = |vx| × 0.8.
  • The brown ball (18 px/frame → 14 px blur) has stronger blur than the grey ball (15 px/frame → 12 px blur).
  • This creates natural-looking horizontal streaks matching the original frame 00 appearance.

6. Output Artifacts

  • frames/00.png – frames/19.png: 20 RGB PNGs at 256×144.
  • pixels.npz: uint32 tensor (144, 256, 20), packed as 0xRRGGBB.
  • inspection.png: 1024×330 contact sheet (8 key frames).
  • transition_check.png: 256×144 — top half: per-frame difference heatmap; bottom half: first/last frame overlay.
  • index.html: Standalone player (via artifact_io.save).
  • generate.py: Self-contained generation script.

Libraries Used

  • numpy: array operations, random number generation
  • PIL (Pillow): PNG I/O, ImageDraw for inspection sheet
  • scipy.ndimage.label: connected-component labelling for sprite extraction
  • artifact_io.save: index.html player output
