METHOD.md

Method — Case 0009: Tennis Ball Hits Rubber Duck

Scene Analysis

The scene is a static locked-off shot of a realistic scientific demonstration. Key elements identified through numeric RGB inspection of first_frame.png (256×144, uint8 RGB):

Element Position Color Profile
Mustard couch (background) rows 0–40, center-right brownish-mustard, RGB ~(80–100, 60–80, 5–30)
Coffee table (foreground) rows 40–143, full width light beige, RGB ~(115–145, 110–140, 100–140)
Black pipe (left side) originates top-left, opening at y≈40–50, x≈0–55 very dark, RGB ~(0–15, 0–15, 0–20)
Yellow rubber duck bbox [163,186]×[52,73], center (174.5, 62.5) bright yellow, RGB ~(190–210, 185–205, 15–45)
Tennis ball not visible in frame 0 (inside pipe) brown

Generation Approach

Ball Rendering

The tennis ball is rendered as a 10-pixel-diameter sphere sprite with:

  • Procedural 3D shading: Per-pixel sphere normals computed analytically, lit from upper-left with diffuse (Lambertian) and specular (Blinn-Phong) components
  • Brown base color: RGB(105, 58, 28) with lighting variation producing highlights up to ~RGB(213, 161, 114) and shadows down to ~RGB(60, 30, 15)
  • Fuzz texture: Subtle sinusoidal modulation (±4%) on the diffuse channel approximates tennis ball surface
  • Edge softening: Anti-aliased alpha blending at the sphere boundary (1.3px falloff)
  • Elliptical shadow: Semi-transparent dark ellipse rendered below the ball at ~75% ball radius, 35% opacity

Alpha Compositing

Ball and shadow sprites are alpha-composited onto copies of first_frame.png using standard over-operator blending. Each frame starts as a full copy of the base image, ensuring unchanged regions remain pixel-identical.

Ball Trajectory

Precomputed piecewise-linear path with physics-inspired speed profile:

  • Frames 1–3: Slow emergence from pipe (3–5 px/frame)
  • Frames 4–10: Constant rolling speed (~8.5 px/frame)
  • Frames 11–14: Gradual deceleration (6→4 px/frame) approaching duck
  • Frame 15: Ball touches duck (right edge contacts duck left edge)
  • Frames 16–19: Ball at rest against duck

Duck Collision Response

When the ball reaches the duck (frames 16–19), the duck is displaced rightward:

  • Frame 16: +1 px shift (initial contact)
  • Frame 17: +2 px shift (maximum displacement)
  • Frame 18: +1 px shift (partial rebound)
  • Frame 19: +1 px shift (settled position)

The displacement is implemented by:

  1. Identifying duck pixels via a yellow color mask on the original frame
  2. Filling the original duck region with table background (sampled from below the duck)
  3. Pasting the yellow duck pixels at the shifted position

Verification

  • Frame 00 equals first_frame.png exactly (verified via np.array_equal)
  • All 20 PNGs validated against the uint32 0xRRGGBB tensor in pixels.npz
  • No black/artifact pixels introduced in the duck region
  • Ball path verified via per-frame diff analysis against frame 0
