Implementation Strategy

  2. Inpaint background behind marble using nearby pixel sampling
  3. Define ramp centerline waypoints for physics simulation

  6. Marble rendering: apply soft alpha blend for anti-aliased edges, preserve specular highlight appearance

METHOD.md

METHOD.md — Marble Run Animation

Approach

The task is to animate a yellow glass marble sliding down magnetic ramps attached to a whiteboard, generating 20 frames (256×144 px, 4 fps) from a single static input frame (first_frame.png).

1. Marble extraction and background inpainting

The marble was identified via colour thresholding in RGB space (warm-yellow glass: R dominates, G intermediate, B lower). A dilated mask captured the full marble including soft edges (363 px). The background behind the marble was inpainted row‑by‑row using linear interpolation between the nearest clean pixels to the left and right of each masked row, preserving the ramp‑surface gradient.

2. Track definition

The centre‑line of the marble‑run track was defined as a polyline of 9 waypoints in image coordinates, tracing the four ramp segments and the free‑fall gaps between them. Waypoints were placed by analysing the spatial distribution of non‑uniform pixel regions in the input frame.

3. Physics simulation

Uniform gravitational acceleration (a = 24 px s⁻²) was applied along the track centre‑line, with the marble starting from rest at t = 0. The simulation advanced in ¼‑second steps (4 fps) using piecewise analytic integration across each track segment. Arc‑length position was converted to (x, y) image coords by linear interpolation along the polyline.

The acceleration was tuned so the marble traverses the full 309 px track in just under 5 s, with a natural ease‑in from rest.

4. Frame generation

For frame 0 the original image is used unchanged. For frames 1–19, the marble sprite (26×20 px RGBA, extracted from frame 0) is alpha‑blended onto the inpainted background at the simulated (x, y) position using nearest‑neighbour placement.

  • inspection.png — 8‑frame keyframe sheet (1024×330)
  • transition_check.png — frame‑to‑frame difference grid
  • index.html — standalone web player
  • generate.py — self‑contained generation script
