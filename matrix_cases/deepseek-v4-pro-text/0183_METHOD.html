METHOD.md

Method

Overview

The task is to generate a 20-frame animation (256×144 px, 4 fps, 5 s) from a single static input (first_frame.png). Frame 00 must be bit-identical to the input. The scene depicts a robotic grabber retracting after placing a blue wooden block on a yellow block (which balances on a red block forming an L-shape).

All operations are local numpy pixel manipulations; no external models, engines, or network access are used.

Object Segmentation

Masks are built from first_frame.png using per-pixel colour thresholds.

Grabber mask (exclusion method)

Within a generous bounding box (x=110–151, y=0–24), a pixel is classified as grabber if it is neither wall nor blue block:

  • Wall: 125 < R < 180, 155 < G < 220, 165 < B < 230 (blue-grey background gradient)
  • Blue block: B > 130, R < 80, G < 130, (B−R) > 80, (B−G) > 30 (deep blue wooden block)

This exclusion strategy naturally captures edge, shadow, and semi-transparent pixels that strict colour thresholds would miss. Result: 666 grabber pixels.

Blue block mask

Core: B > 150, R < 80, G < 130, B−R > 100, B−G > 50. Border: B > 130, R < 100, G < 140, B−R > 50, B−G > 20, excluding core. Combined: ~573 pixels in the region (127,14)–(148,72).

Yellow and red blocks

  • Yellow: R > 180, G > 170, B < 40 → 648 px at (95,66)–(147,82)
  • Red: R > 160, G < 90, B < 60, R−G > 80, y > 25 → 466 px at (111,86)–(129,119)

Background Inpainting

A clean background frame (without the grabber) is created by filling the grabber region column-by-column:

  • Wall behind grabber: For each row y, representative wall colours are sampled from clean left (x=100–109) and right (x=152–163) regions. Each grabber pixel is filled by linear horizontal interpolation between these reference colours.
  • Blue block behind claws: Where the black claw overlaps the blue block, the occluded blue-block colour is recovered by searching vertically for the nearest unobstructed blue-block pixel in the same column.

Animation

  1. An RGBA sprite (42×25 px) is extracted from the grabber region using the grabber mask as the alpha channel.

  2. For each frame, the sprite is alpha-composited onto the clean background at a vertical offset:

    | Frames | Offset | Description | |----------|--------|----------------------------| | 00–01 | 0 | Static hold | | 02 | −1 | Retraction begins | | 03 | −3 | | | 04 | −5 | | | 05 | −7 | | | 06 | −9 | | | 07 | −11 | | | 08 | −13 | Mid-retraction | | 09 | −15 | | | 10 | −17 | | | 11 | −19 | | | 12 | −21 | Mostly off-frame | | 13 | −23 | Final traces visible | | 14–19 | −99 | Grabber fully retracted |

  3. The blue, yellow, and red blocks and all background elements remain stationary in every frame.

Output Verification

  • Frame 00 is verified pixel-identical to first_frame.png via np.array_equal.
  • The pixels.npz file stores a uint32 0xRRGGBB tensor of shape (20, 144, 256); roundtrip verification reconstructs each frame from the packed integer and compares against the original RGB array.
  • Inspection images (inspection.png, transition_check.png) provide visual overviews for quick manual review.
