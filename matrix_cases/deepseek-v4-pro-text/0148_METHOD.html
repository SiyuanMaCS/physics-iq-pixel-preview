+def ball_x_for_frame(t: int) -> float:
+    """Return ball x-centre for frame index t (0–19)."""
+    if t == 0:

+

+    Alpha=0 where the ball does not cover.
+    """
+    d = 2 * radius + 1
+    sprite = np.zeros((d, d, 4), dtype=np.uint8)
+    cy = cx = radius

+    hx, hy = highlight_dir

+    for y in range(d):

METHOD.md — case_0148

Approach

The scene shows a scientific demonstration with a white lampshade on a light wooden table, and a black tube pointing left to right on the left side. A brown tennis ball rolls out of the tube across the entire table.

Method

Scene analysis

  • first_frame.png was inspected via numpy/PIL pixel operations (no image viewing tools used).
  • The black tube occupies rows 51–82, cols 0–15. Tube opening is at approximately x=15, centered at y=66.
  • The brown tennis ball is not visible in frame 00 — it is hidden inside the tube.
  • Strict brown-colour search (R–G > 20, R–B > 25) in the tube-exit region returned zero pixels, confirming the ball starts inside the tube.

Frame generation

All 20 frames (256×144, 4 fps) were generated using pure numpy/PIL pixel operations:

  1. Background: first_frame.png loaded as a uint8 numpy array (144×256×3).
  2. Ball sprite: A 10-pixel-diameter brown tennis ball was pre-rendered as an RGBA sprite with:
    • Spherical Lambertian shading with light direction from the lampshade position (upper-left).
    • Specular highlight component.
    • Subtle sinusoidal texture variation to simulate tennis ball felt.
    • Colour palette: base brown ~RGB(135,95,55), highlight ~RGB(175,135,95), shadow ~RGB(85,55,25).
  3. Compositing: For each frame t=1..19, the ball sprite is alpha-composited onto the background at position (x, y=66) using nearest-neighbour placement. Frame 00 is the unmodified background.
  4. Ball trajectory: Constant horizontal velocity from x=18 (frame 01, just emerged from tube) to x=225 (frame 19, near right edge). A subtle ±0.5px sinusoidal vertical oscillation suggests rolling motion.

Verification

  • Frame 00 is byte-identical to first_frame.png (MD5 confirmed).
  • All 20 frames are valid uint8 RGB at 256×144.
  • pixels.npz contains a (144, 256, 20) uint32 tensor with 0xRRGGBB packed values.
  • transition_check.png montage and inspection.png sheet produced.
