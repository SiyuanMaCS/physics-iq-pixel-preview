Method

  1. Background preparation: Extract "clean" background by inpainting ball regions using nearby pixel colors.
  2. Ball extraction: For each ball, create a circular mask and extract the RGB texture from frame 0.
  3. Animation: For each frame, start from background, composite balls at new positions with sub-pixel bilinear interpolation.
  4. Collision physics: Detect when ball centers are within 2×radius. Apply 1D elastic collision formula (equal mass) to swap x-velocities.

METHOD.md

METHOD.md — Generation Approach

Overview

All 20 frames (256×144 RGB, 4 fps) were generated using Python/PIL with local pixel operations only. No external models, engines, or networks were used.

Technique

Frame 0

Frame 00 is an exact byte-for-byte copy of first_frame.png. Verified with np.array_equal().

Background Inpainting

To create a clean background for animating the balls, the two ball regions were inpainted:

  1. Ball region identification: Circular masks (radius 9 px) centered at the measured ball positions:

    • Brown ball: (y=71, x=52)
    • Grey ball: (y=71, x=77)

  2. Inpainting method: For each pixel inside each ball's circular mask, the surrounding 7×7 window was sampled. Pixels within either ball region (radius + 1) were excluded. The median RGB value of valid surrounding pixels was used as the replacement. The inpainting was applied sequentially (grey ball first, then brown) to handle the overlap region.

  3. Fallback: If the 7×7 window had no valid pixels, an 11×11 window was used.

Ball Texture Extraction

Each ball's RGB texture was extracted from first_frame.png using the same circular masks. The textures capture the actual pixel colors including lighting, shading, and surface details of the tennis balls as rendered in the original scene.

Animation

Trajectories (pre-collision):

  • Brown ball (from left pipe): velocity (+3.0, +0.6) px/frame (rightward, slight downward)
  • Grey ball (from right pipe): velocity (−3.5, +0.4) px/frame (leftward, slight downward)

Collision physics:

  • Collision detected when center-to-center distance < 18 px (2 × radius)
  • 1D elastic collision along the line connecting ball centers
  • Equal mass assumption → normal velocity components are swapped
  • Tangential velocity components are preserved
  • Overlap correction applied to prevent sticking

Post-collision:

  • Brown ball bounces leftward (velocity ≈ −3.5, +0.4)
  • Grey ball bounces rightward (velocity ≈ +3.0, +0.6)

Ball Compositing

For each frame, balls are composited onto the inpainted background:

  1. Bilinear sampling: The ball texture is sampled from the original frame 0 using bilinear interpolation at the sub-pixel ball position. This avoids "jumpy" motion and produces smooth translation.

  2. Edge blending: For pixels near the ball's edge (within 1 px of the radius boundary), alpha blending is applied: result = (1-α) × background + α × ball_color, where α = radius − distance. This produces anti-aliased edges.

  3. Background preservation: Pixels outside the ball's circular mask are left unchanged from the inpainted background.

Verification

  • Frame 00 byte-identical to first_frame.png ✓
  • All 20 frames round-trip correctly through pixels.npz uint32 0xRRGGBB packed tensor ✓
  • Per-frame pixel deltas confirm smooth ball motion (~1200–1900 pixels changed per frame) ✓
  • Sample pixel traces confirm balls move from initial positions, collide, and separate ✓

Outputs

  • frames/00.png–19.png: Individual frame PNGs
  • pixels.npz: Compressed uint32 tensor (144×256×20) in 0xRRGGBB format
  • inspection.png: 8-frame overview sheet (frames 0, 2, 5, 8, 11, 14, 17, 19)
  • transition_check.png: Side-by-side comparison of key frame pairs
  • index.html: Standalone animated player
