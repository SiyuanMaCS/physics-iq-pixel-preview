+  - Inpaint the domino footprint to create a clean background plate.
+  - For frames 1–19, rotate the RGBA domino patch with PIL and
+    alpha-composite it onto the clean plate.
+  - Rotation simulates ~90° clockwise turn over 5 seconds (4 fps).
+"""

+# on the dark platform (R<55). We threshold in the platform region.

METHOD.md

METHOD.md — Domino Magnetic Rotation Scene Generation

Overview

The scene shows a scientific demonstration: a small white/cream plastic domino on a black platform rotates clockwise near a powerful magnet. The camera is static throughout. 20 RGB frames at 256×144 resolution, 4 fps, 5 seconds.

Scene Understanding

The scene was analyzed purely through numeric RGB inspection of first_frame.png (no visual/image tools used):

  1. Background (rows 0–37): Blue/purple gradient wall identified by row-wise color profiling showing R-channel 120–190, G-channel 100–195, B-channel 80–250, with B dominant.

  2. Table surface (rows 38–55 and 80–143): Brown/cream wooden texture with R>G>B, warm tones. Identified by warm color dominance and horizontal extent.

  3. Magnet (rows ~39–85, cols ~85–155): Large bluish metallic object. Identified by pixels where B dominates over both R and G by 15+ units (B>R+15 and B>G+15). Bright highlights near the top fade to darker blue-gray below, consistent with specular reflection on metallic surfaces.

  4. Black platform (rows ~48–80, cols ~100–256): Dark raised surface. Core region has pixel values R<45, G<45, B<60. Left edge boundary traced through brightness gradient.

  5. White/cream domino (rows 54–62, cols 94–104): Small rectangular object on the black platform. Identified by significantly elevated brightness (R>130, G>100, sum>300) relative to the dark platform. Bounding box ~9×11 pixels. Color is cream/tan under warm lighting (R~140–172, G~115–140, B~84–100).

Method: Pixel-Level Domino Rotation

Approach Summary

  • All manipulation is local Python pixel operations (numpy, PIL, scipy)
  • No external AI, physics engines, or reference images used

Step 1: Domino Identification

Binary mask created by thresholding in the platform region:

  • R > 130, G > 100, and (R+G+B) > 300
  • Applied in search window y=[50,68), x=[88,112)
  • Morphological closing (3×3 kernel) to fill small gaps
  • Single dilation iteration for soft edge blending

Step 2: Background Inpainting

The domino footprint in the first frame is inpainted to create a "clean plate":

  • For each domino-masked pixel, find the nearest dark platform pixel (R<60, G<60, B<80) in the platform zone
  • Replace the domino pixel with the nearest dark pixel's color
  • Result: seamless dark platform surface behind where the domino was

Step 3: Rotation Animation (Frames 01–19)

For each frame t (1–19):

  1. Compute rotation angle using ease-in-out timing: angle = 90° × (1 - cos(π × t/18)) / 2
  2. Total rotation: ~90° clockwise over the 19 frames
  3. Create the rotated domino using PIL.Image.rotate() with:
    • BICUBIC resampling for smooth sub-pixel interpolation
    • expand=False to maintain patch dimensions
    • Rotation center set to the domino's center of mass
    • Counter-clockwise sign (PIL convention) negated for clockwise rotation
  4. Alpha-composite the rotated RGBA domino onto the clean background plate
  5. Each frame = background plate pixels replaced by rotated domino where alpha > 0

Step 4: Output Generation

  • Frame 00 verified pixel-identical to first_frame.png (max diff = 0)
  • 20 frames saved as PNG via artifact_io.save()
  • pixels.npz: uint32 packed tensor (144×256×20) with 0xRRGGBB encoding
  • inspection.png: 8-frame preview sheet
  • transition_check.png: 20-frame grid with angle annotations
  • index.html: self-contained HTML player with delta-compressed frames

  • pixels.npz tensor vs all 20 PNGs: 0 pixel difference (consistent encoding)
  • Changed pixels confined to domino region (y~43–71, x~87–108) — no background artifacts
