Teapot Rotation – PixelWorld-Text

Scene

A blue ceramic teapot with a red/orange spout sits on a dark wooden platform against a neutral grey gradient wall. The teapot rotates slowly clockwise (as viewed from above), completing one full 360° revolution over 5 seconds.

Technical approach

1. Background inpainting

A clean background plate is created by per‑row horizontal linear interpolation across the teapot gap. For each row, the colours at the left and right edges of the teapot bounding box are blended linearly across the gap. This produces a seamless background without requiring any external inpainting model.

2. Teapot segmentation

Pixels are classified as wall, table, or teapot using RGB channel relationships:

  • Wall: near‑neutral grey (|R−G|<22, |R−B|<22, |G−B|<22, 90<R<190)
  • Table: brown wood (70<R<140, 45<G<105, 25<B<80, R≥G−12, G≥B−8)
  • Teapot: everything else

Morphological closing, opening, and largest‑connected‑component selection produce a clean binary mask. The mask is dilated by 2 pixels to capture edge detail.

3. Cylindrical rotation model

The teapot is modelled as a texture wrapped around a vertical cylinder of effective radius R = (bbox_width)/2 centred at cx. Each foreground pixel at column x is assigned an angular coordinate φ = arcsin((x−cx)/R), mapping the visible front hemisphere to φ ∈ [−π/2, π/2].

For frame i at rotation angle θᵢ = i·360°/20, a backward mapping is used:

  • For each destination pixel (xd, yd) in the cylinder projection:
    • φd = arcsin((xd−cx)/R) — the pixel's angular position relative to the camera
    • φs = φd − θᵢ — the original angular position of the surface point now at φd
    • xs = cx + R·sin(φs) — source column in the original image
  • Front hemisphere (cos(φs) > 0): pixel comes from the original front texture at (xs, yd)
  • Back hemisphere (cos(φs) < 0): pixel comes from a horizontally mirrored version of the front texture, but only when the view is predominantly the back (cos(θᵢ) < −0.3). For side views, back‑hemisphere pixels are omitted, creating a naturally thin profile.

4. Hole filling

After remapping, small gaps caused by discretisation and occlusion are filled. The rendered mask is dilated and eroded to form a connected region, then any remaining background‑coloured pixels inside the region are filled by averaging neighbouring teapot‑coloured pixels.

5. Output encoding

  • PNG frames: 256×144 uint8 RGB, saved as frames/00.png–19.png
  • pixels.npz: uint32 tensor of shape (144, 256, 20) packed as 0xRRGGBB
  • index.html: standalone player using delta‑encoded uint32 frame data with the provided player template
