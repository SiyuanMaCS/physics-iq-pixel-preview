METHOD.md — Approach & Implementation

Overview

The animation is generated by constructing a clean background image (table and scene without stick or dominoes), then compositing the stick and dominoes at their animated positions for each frame. Frame 00 is the original first_frame.png; all subsequent frames are built independently starting from the clean background.

1. Foreground Pixel Identification

Stick Detection

Stick pixels are identified by a color-threshold classifier operating on the original frame 00. The stick has a characteristic wood-brown hue (R > G > B) with medium brightness:

  • R: 70–170, G: 40–140, B: 20–120
  • Additional exclusion: R > 110 && G > 90 (avoids wood-table confusion)
  • Search area: rows 30–72, columns 10–68

This yields 48 stick pixels with bounding box x=[10–67], y=[35–63]. The stick pivot point is estimated at (15, 33).

Domino Bounding Boxes

Seven dominoes are defined by rectangular bounding boxes measured from frame 00:

Name Color x-range y-range
F0 Black 63–72 44–63
F1 White 71–80 44–67
B0 Black 84–93 48–69
B1 White 98–106 55–71
B2 Black 130–137 56–78
B3 White 143–151 59–76
B4 Black 148–163 64–85

The full foreground mask is the union of all stick pixels and all domino bounding boxes.

2. Clean Background Construction

A "clean" version of the scene is built by filling every foreground pixel with an interpolated color derived from neighboring non-foreground columns in the same row.

Margin-Aware Horizontal Interpolation

For each row, contiguous runs of foreground pixels are identified. For each run:

  1. Find boundaries: scan left from the leftmost foreground column until hitting a non-foreground column; scan right from the rightmost foreground column similarly.
  2. Apply margin: step back an additional 3 pixels from each boundary to avoid shadow/border artifacts near object edges.
  3. Interpolate: for each column in the foreground run, linearly interpolate between the left and right reference pixel colors:
    color(x) = left_color * (1 - frac) + right_color * frac
where frac = (x - left_ref) / (right_ref - left_ref)
  4. Edge cases: if only one side has a reference, all foreground columns use that single reference color.

This margin-aware approach ensures that dark shadow pixels at object borders (e.g., at row 46, x=62 between the stick and F0) are not propagated across the entire erased region. Instead, the reference pixel at x=60 (proper wood color) is used.

Rotation uses the standard 2D rotation matrix:

new_x = pivot_x + (x - pivot_x) * cos(angle) + (y - pivot_y) * sin(angle)
new_y = pivot_y - (x - pivot_x) * sin(angle) + (y - pivot_y) * cos(angle)

Note: clockwise rotation uses +sin for x and −sin for y.

4. Frame Generation Pipeline

For each frame t (1–19):

  1. Start from clean background: copy the pre-built clean background.
  2. Draw stick: rotate all 48 stick pixels by stick_angles[t] and draw them at integer-rounded coordinates.
  3. Draw dominoes: for each domino:
    • If angle < 0.005 rad: draw the full original sprite (upright).
    • If angle > π/2 − 0.015 rad: skip drawing (fully flat, invisible from top-down view).
    • Otherwise: vertically compress the sprite to new_height = max(2, int(original_height * cos(angle))) using PIL's bilinear resize, then draw bottom-aligned at the original x-position.
