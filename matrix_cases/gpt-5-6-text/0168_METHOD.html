+# Numerically measured center and radius of the tennis ball.

+ANGLE_STEP_DEG = 3.0
+INNER_RADIUS = 16.2
+OUTER_RADIUS = 17.4

+def smoothstep(edge0, edge1, values):
+    x = np.clip((values - edge0) / (edge1 - edge0), 0.0, 1.0)
+    return x * x * (3.0 - 2.0 * x)
+

+def make_frames():
+    """Rotate the measured spherical ball region clockwise at constant speed."""
+    yy, xx = np.indices((HEIGHT, WIDTH), dtype=np.float64)
+    dx, dy = xx - CX, yy - CY
+    radius = np.hypot(dx, dy)
+
+    # Fully animated in the ball interior, smoothly returning to the exact source
+    # across the antialiased edge. No pixel beyond OUTER_RADIUS is touched.
+    alpha = 1.0 - smoothstep(INNER_RADIUS, OUTER_RADIUS, radius)
+    alpha = alpha[..., None]
+    source_f = SOURCE.astype(np.float64)
+    channels = [SOURCE[..., c].astype(np.float64) for c in range(3)]
+
+    frames = np.empty((N_FRAMES, HEIGHT, WIDTH, 3), dtype=np.uint8)
+    frames[0] = SOURCE
+    for frame_no in range(1, N_FRAMES):
+        theta = np.deg2rad(ANGLE_STEP_DEG * frame_no)
+        c, s = np.cos(theta), np.sin(theta)
+
+        # Inverse map for a visually clockwise screen-space rotation.
+        src_x = CX + c * dx + s * dy
+        src_y = CY - s * dx + c * dy
+        coords = np.stack((src_y, src_x), axis=0)
+        rotated = np.stack(
+            [map_coordinates(ch, coords, order=3, mode="reflect", prefilter=True)
+             for ch in channels],
+            axis=-1,
+        )
+        composited = source_f * (1.0 - alpha) + rotated * alpha
+        frames[frame_no] = np.clip(np.rint(composited), 0, 255).astype(np.uint8)
+    return frames

OBSERVATION.md

Numeric observation and event plan

Inspection method

I inspected first_frame.png only by loading its RGB array locally with Pillow/NumPy and printing numeric statistics, threshold masks, connected-component bounds, scan-line samples, and a character map. I did not use an image viewing or image-reading tool.

Scene measurements

  • Source is RGB, 256 x 144. Channel means are approximately (132.60, 109.20, 86.11) and the corner samples range from gray (83,83,85) to warm brown (136,93,59).
  • The yellow-green ball is the single connected component selected by G > 0.90R, G > 1.30B, R > 55: 892 pixels, bounding box x=122..155, y=47..81, centroid (139.14,64.28). A circle centered at (139,64) with radius 17 pixels covers it closely.
  • Within radius 17, about 94.6% of pixels satisfy the yellow-green test. Its mean RGB there is about (165,172,46); the brightest measured ball sample is near (220,228,52) on the right side, while the left/lower side is shaded.
  • The face consists of three dark components against the ball: two upper marks around x=126..129,y=51..56 and x=130..135,y=52..58, plus a curved lower mark around x=124..133,y=65..71.
  • The main dark connected component (black platform plus contact/shadow) spans approximately x=103..184, y=68..119, centroid (140.75,93.81). It remains static.
  • Everything outside the ball is a locked background. The output camera, framing, exposure, and platform remain fixed.

Motion design

The ball rotates clockwise in the image plane at a constant slow rate of 3 degrees per frame (12 degrees/second). The rotation is centered at (139,64). The interior is resampled bicubically; a narrow radial feather from radius 16.2 to 17.4 pixels preserves the spherical silhouette and avoids disturbing the platform/background. Frame 00 is copied byte-for-byte from the source RGB array.

METHOD.md

Method

Source inspection

I used Pillow and NumPy to inspect first_frame.png as numeric RGB data only. I printed image dimensions, channel statistics, thresholded connected components, bounding boxes, sampled scan lines, and an ASCII classification map. I did not use an image Read/View tool and did not visually review the source or outputs.

The numeric analysis found the tennis ball at approximately (139,64) with radius 17 pixels, the face markings on the upper-left/left portion of that disk, and the dark platform below it. Those measurements are recorded in OBSERVATION.md.

Animation construction

generate.py loads the source RGB image and keeps the camera and every pixel outside the measured ball disk locked. For each frame after frame 00:

  1. It applies a constant clockwise angle of 3 degrees * frame_index about (139,64).
  2. It inverse-maps the original ball pixels with cubic interpolation (scipy.ndimage.map_coordinates, order 3).
  3. It uses the rotated result fully through radius 16.2 pixels, then smoothly feathers it back to the exact source over radii 16.2–17.4 pixels. This keeps the spherical outline stable and prevents changes to the platform or surrounding scene.
  4. It rounds and clips the result to RGB uint8.

Frame 00 is assigned directly from the decoded source array without resampling. The ball rotates a total of 57 degrees across the 20-frame real-time sequence; there are no cuts, camera movements, or other events.

Packaging and checks

The supplied artifact_io.save helper creates:

  • pixels.npz as a (144,256,20) uint32 tensor packed as 0xRRGGBB
  • twenty RGB PNG frames in frames/
  • inspection.png
  • the standalone index.html player at 4 fps

generate.py also creates transition_check.png, whose upper panels contain representative destination frames and whose lower panels contain 7x-amplified absolute RGB differences for four one-frame transitions.

Automated verification performed after saving:

  • frame array shape is (20,144,256,3) and dtype is uint8
  • frames/00.png is exactly equal to first_frame.png after RGB decode
  • all pixels at radius 17.4 or greater from the ball center are identical in all 20 frames
  • each PNG exactly equals its corresponding slice of the packed uint32 tensor
  • one-step changed-pixel bounds remain x=122..156, y=47..81
  • per-step mean absolute change within the ball disk is stable at roughly 4.53–4.72 RGB levels
  • the dark face-feature centroid progresses from about (130.38,64.01) toward (134.17,56.88), numerically confirming clockwise motion from the left side toward the top

No visual-review claim is made; quality and compliance were checked numerically.
