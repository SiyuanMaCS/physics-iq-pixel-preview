+def rgba_layer(draw_callback):
+    """Draw one high-resolution RGBA layer and downsample it smoothly."""
+    layer = Image.new("RGBA", (W * SCALE, H * SCALE), (0, 0, 0, 0))
+    draw = ImageDraw.Draw(layer, "RGBA")
+
+    class ScaledDraw:
+        def polygon(self, points, fill):
+            draw.polygon([(round(x * SCALE), round(y * SCALE)) for x, y in points], fill=fill)
+
+        def ellipse(self, box, fill, outline=None, width=1):
+            box = tuple(round(v * SCALE) for v in box)
+            draw.ellipse(box, fill=fill, outline=outline, width=max(1, round(width * SCALE)))

+        def line(self, points, fill, width=1, joint="curve"):
+            points = [(round(x * SCALE), round(y * SCALE)) for x, y in points]
+            draw.line(points, fill=fill, width=max(1, round(width * SCALE)), joint=joint)

+def irregular_ellipse(cx, cy, rx, ry, phase, count=36):
+    points = []
+    for i in range(count):
+        angle = 2.0 * math.pi * i / count
+        wobble = 1.0 + 0.055 * math.sin(3 * angle + phase) + 0.035 * math.sin(7 * angle - phase)
+        points.append((cx + rx * wobble * math.cos(angle), cy + ry * wobble * math.sin(angle)))
+    return points

+def make_duck_mask(source):
+    """Derive the photographed duck silhouette from numeric RGB thresholds."""
+    a = np.asarray(source, dtype=np.uint8)

METHOD.md

Method

Actual generation method

I used only local Python code and numeric RGB inspection. I did not use an image Read/View tool, external model, external engine, mask, reference, network call, or another case.

generate.py loads first_frame.png with Pillow and preserves it as the full background of every frame. Frame 00 is a direct uint8 copy and is asserted to be exactly equal to the decoded source RGB array.

The duck silhouette is found from the source pixels by a saturated-yellow RGB threshold, connected-component labeling, and selection of the component in the measured duck region. Binary closing, hole filling, and one-pixel dilation make a stable coating mask. This mask is derived entirely from first_frame.png and is used only to keep procedural runoff on the photographed rubber surface.

The added bright-red liquid is deterministic vector/raster drawing:

  • a forming bead, narrow stream, steady stream, thinning rope, and final drop at the measured pour axis;
  • clipped crimson/scarlet runoff paths across the duck with narrow specular highlights;
  • a lower-breast drip and a few tiny ballistic splash beads;
  • an irregular, expanding puddle on the dark tray, layered from deep shadow red through scarlet reflection, with the original duck masked out so the puddle remains behind it.

All liquid primitives are drawn at 4x resolution, downsampled with Lanczos filtering, and alpha-composited over the unmodified photograph. Geometry varies with deterministic sine functions and smoothstep growth curves; there is no random input. The camera and all photographed setup pixels outside the local action rectangle remain fixed.

Timing

The sequence has 20 frames at 4 fps (5 seconds by the task convention). The pour starts as a bead, becomes continuous, coats the duck, drains into an expanding tray puddle, thins, stops, and leaves residual wet paths and a settled puddle. The exact per-frame plan is recorded in OBSERVATION.md.

Output and verification

artifact_io.save writes pixels.npz, frames/00.png through frames/19.png, inspection.png, and the standalone index.html player. generate.py also writes transition_check.png, whose top row contains nearest- neighbor enlargements of the measured action crop and whose bottom row contains 3x-amplified numeric RGB differences from frame 00.

The generator performs these assertions after writing:

  1. tensor shape is (20, 144, 256, 3) and dtype is uint8;
  2. frame 00 exactly equals first_frame.png after RGB decoding;
  3. every consecutive pair changes and all changes are confined to the local dispenser/duck/tray action rectangle;
  4. pixels.npz has shape (144, 256, 20), dtype uint32, and exactly equals the frames packed as 0xRRGGBB then transposed;
  5. every saved PNG decodes back to the corresponding generated RGB frame.

The final verification was numeric only. No claim of visual review is made.
