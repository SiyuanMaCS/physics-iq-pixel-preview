Actual generation method

The animation is a deterministic native-resolution RGB compositing workflow implemented in generate.py with NumPy, Pillow, and OpenCV. I did not use an external model, engine, reference image, mask, score, network resource, or image viewing tool.

  1. I loaded first_frame.png as a 256 x 144 uint8 RGB array and measured the scene using numeric RGB row profiles, connected components, color relations, and coordinate samples.
  2. I recorded the observations and the 20-frame physical event schedule in OBSERVATION.md before writing generation code.
  3. I manually defined close silhouette polygons for the six measured block regions. Each sprite takes its RGB texture directly from the source frame and uses a lightly feathered alpha edge.
  4. I represented the visible wooden arm by a measured rounded 7 px strip from approximately (199,54) to (177,75). Its source texture is likewise retained.
  5. For frames after frame 00, I made a locked clean plate by dilating only the object/arm masks and using deterministic Telea inpainting over those compact regions. Pixels outside the restoration mask remain exactly equal to the source.
  6. The arm rotates clockwise in image space around (199,54), moving through a 38-degree sweep with a one-degree damped correction at its stop.
  7. Each block rotates left about its measured bottom contact. An eased angle curve—4, 14, 28, 44, 59, 71, 79, 83 degrees followed by a damped 81/82-degree settle—is offset by two frames per block, beginning with purple and propagating right-to-left through blue, green, pink, red, and yellow.
  8. Soft blurred shadows are generated from each transformed alpha mask and clipped away from the wall. Blocks are composited left-to-right so the right-hand block correctly overlaps the block it has just struck.
  9. Frame 00 is not reconstructed: it is a direct byte-for-byte RGB array copy of first_frame.png.

Artifact and verification method

  • artifact_io.save packs each RGB pixel into uint32 0xRRGGBB, transposes it to (144,256,20), and writes pixels.npz, the 20 PNG frames, inspection.png, and the standalone index.html player.
  • transition_check.png contains twelve selected full frames plus four 4x-amplified consecutive-frame difference maps. It is a generated diagnostic artifact, not a claim of visual review.
  • The generator reloads every PNG and pixels.npz, reconstructs the packed tensor independently, and asserts exact equality with the in-memory uint8 frames.
  • It separately asserts that frame 00 exactly equals the decoded source and that every consecutive pair contains changed pixels.

The final verification run reported frame-00 RGB SHA-256 dc97a92b9f5aa571d5e5539060142c518ca292d70d559d02bfb65acefd778d0a. All 20 decoded PNG arrays matched the packed tensor exactly. Consecutive changed-pixel counts were 450, 1550, 1879, 2495, 2591, 3113, 3000, 3848, 3667, 3754, 3524, 3982, 3814, 3356, 3306, 2845, 2642, 1939, 1782; the compact 450-pixel first transition is confined to the rotating arm while unstruck blocks stay source-exact.
