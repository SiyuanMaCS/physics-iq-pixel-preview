duck-static · 生成方法

The sequence is generated by exact RGB hold-frame duplication.

generate.py loads first_frame.png as its native 256 x 144 RGB uint8 array and repeats that array 20 times along a new time axis. This implements the prompt literally: the shot is locked off, its frame is fixed, and the rubber duck remains stationary throughout the five-second real-time interval. No interpolation, repainting, crop, filtering, lighting modulation, noise, or camera jitter is applied.

The supplied artifact_io.save helper writes the pixels.npz tensor, individual PNG frames, contact sheet, and standalone HTML player. The script additionally creates transition_check.png, showing frames 00, 01, 10, and 19 plus the changed-pixel counts for every consecutive transition.

The script then verifies all of the following programmatically:

  • frame array shape is (20, 144, 256, 3) and dtype is uint8;
  • frame 00 exactly equals first_frame.png at every RGB sample;
  • pixels.npz is uint32, has shape (144, 256, 20), and stores every sample as 0xRRGGBB;
  • each of the 20 decoded PNGs exactly equals its corresponding packed tensor plane;
  • each of the 19 consecutive transitions has zero changed pixels, as required by the stationary event plan.

Scene analysis and output validation were performed from decoded numeric RGB data and code-generated statistics. No image viewing tool was used, so no visual-review claim is made.
