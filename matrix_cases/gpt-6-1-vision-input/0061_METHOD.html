duck-static · 生成方法

The prompt specifies a stationary rubber duck on a wooden table with a locked camera and fixed framing. All 20 frames therefore use the exact RGB pixels of the provided first frame. The method is direct NumPy pixel repetition; there is no synthesized movement, camera transform, relighting, or noise. Only first_frame.png and prompt.txt were used as scene inputs.

generate.py loads the 256 × 144 RGB source with Pillow and repeats it 20 times. The supplied artifact_io.py writes the PNG sequence, inspection sheet, packed tensor, and standalone HTML player. The first PNG is also copied from the original file so it is byte-identical. A separate transition sheet shows frames 00/01, 09/10, and 18/19, with their absolute RGB difference panels. Black difference panels mean zero change. Frames are displayed at 4 fps, each held for 0.25 seconds, for a total of 5 seconds.

Numeric verification

  • Exactly 20 RGB PNGs, each 256 × 144 pixels.
  • pixels.npz contains the pixels array with shape (144, 256, 20), dtype uint32, and encoding 0xRRGGBB, with axes (height, width, time).
  • All 20 PNGs exactly match the unpacked tensor and source RGB pixels.
  • frames/00.png is also byte-identical to first_frame.png.
  • All 19 transitions change zero pixels; maximum channel difference is 0.
  • All 20 HTML player frames were decoded locally and match the tensor.
  • Source panels in inspection.png and transition_check.png were checked against frame arrays. All three transition difference panels are zero.
  • Source RGB SHA-256: 55ee6208cbfb9c764d15be533bc104ec94958c957eb8bbb404d4d6ddfc80a85d.

The supplied initial image was observed visually in the user attachment. Generated outputs were checked only through local code and numeric analysis; no generated image was opened using an image Read/View tool. No external models, engines, references, network access, or subagents were used.
